# v2.3 Distribution & Publishing — Security Review

**Status:** SKIPPED (co-driver decision, 2026-07-05)

## Decision
The dedicated milestone-close security review was **skipped by co-driver decision** at the
milestone-close gate.

## Rationale (co-driver + architect)
- v2.3 is a **TypeScript packaging + documentation** milestone: it extracts a shared core,
  adds a second host adapter, makes the packages publish-ready, and corrects docs. It makes
  **no change to the Go binary, the browser engine, or the stealth surface**.
- The extensions' **trust boundary is unchanged from v2.2** (which passed its security review,
  `.planning/v2.2-SECURITY.md`): each extension shells out to the `rod-cli` binary via the
  host's `exec`, with client-side input validation and the `--` injection separator between
  flags and user-controlled values. In v2.3 that separator is **centralized in the core
  argv-builders** (verified: every builder preserves `--`; the B51-1 fix actually *restored*
  validation that was silently defeated) — a net improvement to the boundary, not a regression.

## Surface introduced by v2.3 (noted, not audited)
- **Publish workflow (`publish-extensions.yml`):** uses `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`
  scoped to the publish steps, `permissions: { contents: read }` (least-privilege), triggered
  only on `ext-v*` tags (disjoint from the Go `v*` trigger). The live token/org do not exist yet.
- **Dependency hygiene (PI-02):** Pi's runtime schema-libs (`typebox`, `@earendil-works/pi-ai`)
  are declared as real `dependencies` pinned to public-npm versions; `peerDependencies:"*"` was
  removed. No new untrusted runtime dependency was added; the core has zero runtime deps.

If a security pass is desired later, these two areas (publish-token handling + supply-chain
of the declared deps) are the recommended focus.
